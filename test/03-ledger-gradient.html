Der Ablauf

Drei Schritte, die man später noch nachvollziehen kann.

Der Unterschied zwischen einer Zahlung und einem Beleg: der zweite sagt, was passiert ist — und warum es wieder passieren darf.

0103
01

Anfordern, mit Schlüssel

Ein Aufruf, ein Idempotenzschlüssel. Wird derselbe Schlüssel erneut gesendet, entsteht keine zweite Buchung — egal wie oft das Netzwerk zickt.

create.tsIdempotency-Key
const payment = await ledger.charges.create({
  amount: 24900,
  currency: 'eur',
  source: 'card_4242',
}, {
  idempotencyKey: order.id,
});

Gleicher Schlüssel, gleiche Antwort — auch nach 24 Stunden.

02

Bestätigen, mit Signatur

Der Webhook kommt mit Zeitstempel und Signatur. Wird beides geprüft, kann niemand eine Zahlung vortäuschen, die es nicht gibt.

webhook.tsv1 signiert
const event = ledger.webhooks.verify({
  payload: body,
  signature: headers['ledger-signature'],
  secret: env.LEDGER_SECRET,
});

if (event.type === 'charge.succeeded') {
  await orders.fulfil(event.data.order);
}

Zeitfenster 300 Sekunden, Replays werden abgewiesen.

03

Abgleichen, jeden Tag

Der Tagesabschluss paart Zahlung, Auszahlung und Rechnung. Was nicht passt, steht sichtbar in einer Liste — nicht in einer E-Mail.

reconcile.sh22:00 UTC
# Tagesabschluss, Exit-Code 0 bei Übereinstimmung
ledger reconcile \
  --date 2026-10-14 \
  --against ledger.csv \
  --strict

Differenzen mit Betrag, Grund und Referenz — exportierbar.
